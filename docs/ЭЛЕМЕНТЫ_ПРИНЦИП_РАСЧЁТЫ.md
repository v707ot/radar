# Элементы, принцип работы, расчёты и схема работы

Автономный датчик оповещения о малой высоте БПЛА (сигнальный).
Документ отвечает на три вопроса: **из чего состоит**, **как работает и почему
выполняет ТЗ** (с расчётами), **как выглядит схема работы**.

> Назначение — только **сигнализация**. Выходы: зуммер, LED, дискретный флаг,
> CAN-телеметрия. Исполнительных/инициирующих цепей нет.

## 2. Принцип работы

### 2.1. Общий принцип

1. Датчик непрерывно измеряет **дистанцию до земли** `L` (высоту `h`).
2. MCU фильтрует отсчёты (медиана → при необходимости Калман).
3. Сравнивает высоту с порогом `H_ср`, заданным по CAN (2…10 м).
4. При `h ≤ H_ср` формирует **сигнал**: зуммер, LED, дискретный флаг, CAN-сообщение.
5. При пропадании данных дольше таймаута → **Fail-Safe** (аварийный флаг).

### 2.2. Принцип измерения — лидар (ToF, время пролёта)

Дальность вычисляется по времени прохождения импульса туда-обратно:

```
t = 2·h / c        →        h = c·t / 2
```

где `c = 3·10⁸ м/с`. Для нашей высоты:

| Высота h | Время t = 2h/c |
|---|---|
| 2 м | 13,3 нс |
| 10 м | 66,7 нс |

Время пролёта — наносекунды, поэтому лидар считает его прецизионным таймером
(а не «ждёт эхо»). Модуль отдаёт уже готовую высоту по UART.

**Поле зрения (пятно):** FoV TFmini-S ≈ 3,6°, диаметр пятна на земле
`D = 2·h·tg(FoV/2)`:

| h | Пятно D |
|---|---|
| 2 м | 12,6 см |
| 10 м | 63 см |

Пятно < 1 м — требование точности не нарушается даже на наклонной местности.

**Лазерная безопасность:** 905 нм, класс 1 (IEC 60825-1) — безопасен для глаз.

### 2.3. Принцип измерения — радар (FMCW)

FMCW-радар излучает непрерывный сигнал с линейной частотной модуляцией.
Дальность — из разностной частоты `f_b`, разрешение по дальности:

```
ΔR = c / (2·B)
```

| Радар | Полоса B | Разрешение ΔR |
|---|---|---|
| 24 ГГц (NRA24) | ~250 МГц | 0,60 м |
| 60 ГГц (A121) | ~1,5 ГГц | 0,10 м |

Для 24 ГГц разрешение 0,6 м; с интерполяцией по SNR достигается ~0,1…0,2 м.
Требование ≤1 м выполняется обоими.

### 2.4. Алгоритм обработки

1. **Приём** кадра (UART через DMA, 9 байт).
2. **Валидация**: контрольная сумма, диапазон, сигнал (strength).
3. **Медиана** по 3 отсчётам — отсекает выбросы.
4. **Фильтр Калмана** (опция) — сглаживает шум и даёт вертикальную скорость `v`.
5. **Сравнение с порогом** с гистерезисом ΔH = 0,3 м (защита от «дребезга»).
6. **Предиктивное упреждение** (компенсация задержки): срабатывание, если
   `h + v·T_задержки ≤ H_ср`.
7. **Выдача** сигналов (зуммер, LED, флаг, CAN).

## 3. Расчёты по требованиям ТЗ

### 3.1. Требование 1: H_сраб = 2…10 м с варьированием

- **Диапазон уставки:** 2,0…10,0 м.
- **Шаг:** 0,1 м → 81 значение (при погрешности датчика ±0,06 м шаг 0,1 м достаточен).
- **Кодирование по CAN:** `uint16` в миллиметрах (2000…10000), запас точности 1 мм.
- **Диапазон датчика** должен покрывать уставку с запасом:
  `L_max ≥ H_ср_max + запас`. Для TFmini-S `L_max = 12 м > 10 м` ✅.
- **Хранение уставки:** в EEPROM/флеш MCU, сохраняется при отключении питания.

### 3.2. Требование 2: тип датчика (помехозащищённый, см/мм или лазер)

- **Лидар 905 нм** — узкий луч (3,6°), помехозащищён от чужих сигналов, но
  зависит от погоды (туман, пыль, дождь).
- **Радар 24/60 ГГц** — всепогодный, помехозащищён, работает сквозь пыль/дождь.
- **Ультразвук и CW-доплер — не применять** (см. `СРАВНЕНИЕ_ДАТЧИКОВ_CN.md`, раздел 0).

### 3.3. Требование 3: погрешность ≤ 1 м

**Важно:** итоговая погрешность определяется **всеми** источниками, а не только
ошибкой датчика. Ниже учтены все четыре составляющие.

Бюджет погрешностей (сумма квадратов — независимые источники):

```
ε = √(ε_датчика² + ε_наклона² + ε_динамики² + ε_цели²)
```

| Составляющая | Значение | Примечание |
|---|---|---|
| ε_датчика (TFmini-S) | ±0,06 м | паспорт ±6 см |
| ε_наклона (α = 5°) | 0,04 м | `h·(1/cos α − 1)`, h = 10 м |
| ε_наклона (α = 10°) | 0,15 м | без компенсации по IMU |
| ε_динамики | 0,10 м | **снижение 3 м/с × задержка 33 мс** ⚠️ |
| ε_цели (трава, склон, вода) | 0,05…0,30 м | зависит от рельефа и материала |
| ε_шума (С/Ш) | 0,02 м | для лидара на 10 м |

**Расчёт по вариантам (сумма квадратов всех составляющих):**

| Условия | Расчёт | ε, м | ≤ 1 м? |
|---|---|---|---|
| Наклон 5°, ровная твёрдая земля, зависание | √(0,06²+0,04²+0,02²) | **0,08** | ✅ |
| Наклон 5°, ровная земля, снижение 3 м/с | √(0,06²+0,04²+0,10²+0,02²) | **0,13** | ✅ |
| Наклон 10°, трава/склон, снижение 3 м/с | √(0,06²+0,15²+0,10²+0,30²) | **0,36** | ✅ |
| Наклон 10°, вода (зеркальное отражение) | — | **отказ** | ❌ |

**Ключевые выводы (исправление):**

1. **ε_динамики нельзя опускать.** При снижении 3 м/с и задержке датчика 33 мс
   (номинал 30 Гц) высота «уходит» на 0,10 м ещё до реакции. Это заметная доля
   бюджета, и она входит в итог.
2. **ε_цели — доминирующий источник** на пересечённой местности (до 0,30 м):
   трава, кусты, наклонный склон дают ложную высоту.
3. **Вода/зеркальная поверхность** — не «погрешность», а **отказ измерения**
   (луч не возвращается). Требование формально не нарушено, но прибор не работает.
4. **Наихудший реалистичный случай (0,36 м)** — требование ≤1 м выполняется
   с запасом ~2,8×. Но запас **не 14×**, как в первоначальной (ошибочной) оценке,
   где учитывались лишь датчик и наклон.

> **Компенсация** (улучшает бюджет): учёт наклона по IMU (`h = L·cos θ`) и
> динамическое упреждение (`h + v·T`) убирают ε_наклона и ε_динамики.

> ⚠️ **Что подтвердить.** Для гарантии ≤1 м на реальной местности нужен натурный
> пролёт над травой/склоном — расчёт даёт оценку, но ε_цели зависит от рельефа.

### 3.4. Требование 4: время реакции ≤ 1 мс (ФИЗИЧЕСКАЯ реакция)

**Уточнено заказчиком:** нормируется **физическая** реакция — от фактического
изменения высоты до начала звука. Это самое жёсткое требование ТЗ.

```
T_реакции = T_датчика + T_передачи + T_обработки + T_выдачи ≤ 1 мс
```

| Составляющая | Формула | Значение |
|---|---|---|
| T_датчика | 1/f_обн (ожидание кадра) | зависит от частоты |
| T_передачи | N·10 / baud | 9 байт → см. ниже |
| T_обработки | разбор + медиана + сравнение | ~10…20 мкс |
| T_выдачи | переключение выхода | ~5 мкс |

**Расчёт передачи кадра** (9 байт, старт+стоп = ×10):

| Baud | Время передачи кадра |
|---|---|
| 115 200 | 781 мкс |
| 921 600 | 98 мкс |
| 3 000 000 | 30 мкс |

**Какой датчик нужен.** Чтобы уложиться в 1 мс, частота обновления должна быть:

```
1/f_обн ≤ 1 мс − (T_передачи + T_обработки + T_выдачи)
1/f_обн ≤ 1 000 − (98 + 20 + 5) = 877 мкс
f_обн ≥ 1 140 Гц   (при 921 600 бод)
```

| Вариант | f_обн | Baud | T_реакции | ≤ 1 мс (физически)? |
|---|---|---|---|---|
| TFmini-S, номинал | 100 Гц | 115 200 | ~10,8 мс | ❌ |
| TFmini-S, макс | 1 000 Гц | 921 600 | ~1,12 мс | ❌ **не проходит** |
| Лидар ≥2 кГц (напр. TF03-180 в быстром режиме) | 2 000 Гц | 921 600 | ~0,62 мс | ✅ |
| Радар 60 ГГц A121 (быстрый чирп) | ~2 000 Гц | SPI | ~0,5 мс | ✅ |

**Вывод (исправлено):** при **физической** трактовке **TFmini-S не проходит**
(1,12 мс > 1 мс). Нужен датчик с частотой **≥2 кГц** и быстрым интерфейсом.

**Кандидаты, проходящие по реакции:**

| Датчик | Тип | f_обн | Интерфейс | Реакция | Проходит? |
|---|---|---|---|---|---|
| **Acconeer A121 (XM125)** | радар 60 ГГц | до ~2 кГц | SPI | ~0,5 мс | ✅ |
| **TF03-180** | лидар | до ~1 кГц ⚠️ | UART/CAN | ~1,0 мс | ⚠️ проверить |
| Радар 24 ГГц NRA24 | радар | ~50…100 Гц | UART/CAN | 10…20 мс | ❌ |
| VL53L5CX (кольцо 360°) | ToF-матрица | ~60 Гц | I²C | ~17 мс | ❌ (только стены) |

**Рекомендация:** для канала «вниз» (реакция ≤1 мс) — **радар 60 ГГц A121**
(SPI, быстрый чирп, всепогодный). Кольцо стен/потолка работает отдельно и на
требование ≤1 мс не влияет (см. `КРУГОВОЙ_ОБЗОР_360.md`).

> ⚠️ **Что подтвердить.** Частота «≥2 кГц» — расчётная. Нужно подтвердить по
> паспорту конкретного модуля и **измерить натурно**: время от изменения высоты
> до звука. До испытания пункт — «выполним при датчике ≥2 кГц».

> ⚠️ **Ключевое уточнение.** Расчёт ниже — **без аккумулятора**, при питании от
> бортовой сети БПЛА. Если «автономный» означает **работу без борта** (со своим
> питанием), масса вырастет — см. раздел 3.5а.

| Позиция | Масса, г |
|---|---|
| Датчик TFmini-S | 11 |
| MCU STM32G474 | 1 |
| PCB 4 слоя 45×40 мм | 12 |
| CAN-трансивер + обвязка | 2 |
| DC-DC + защита | 3 |
| Зуммер | 3 |

### 3.5а. Автономность: масса с аккумулятором (задано 3 ч)

**Уточнено заказчиком:** автономность = **3 часа**. Считаем батарею при
потреблении ≈ 0,43 Вт (см. 3.8):

```
E = P·t / η = 0,43 Вт · 3 ч / 0,85 ≈ 1,52 Вт·ч
```

При LiPo 1S (3,7 В) нужна ёмкость:

```
C = E / U = 1,52 / 3,7 ≈ 410 мА·ч
```

С запасом 20 % на деградацию и холод: **C ≈ 500 мА·ч**.

| Батарея | Ёмкость | Масса | Ресурс | Итого масса | ≤ 100 г? |
|---|---|---|---|---|---|
| LiPo 1S 400 мА·ч | 1,48 Вт·ч | ~10 г | 2,9 ч | ~86 г | ⚠️ меньше 3 ч |
| **LiPo 1S 500 мА·ч** | 1,85 Вт·ч | **~12 г** | **3,7 ч** | **~88 г** | ✅ **рекомендуется** |
| LiPo 1S 600 мА·ч | 2,22 Вт·ч | ~14 г | 4,4 ч | ~90 г | ✅ |

**Вывод:** для 3 ч автономности достаточно **LiPo 1S ~500 мА·ч (≈12 г)**.
Масса комплекта ≈ **88 г ≤ 100 г** ✅ (с кольцом 360° — см. `КРУГОВОЙ_ОБЗОР_360.md`,
там итог 81 г с запасом 19 г).

> ⚠️ **На холоде ёмкость LiPo падает на 20…30 %.** При −20 °C расчётные 3 ч
> превращаются в ~2,1…2,4 ч. Для гарантии — батарея на 700 мА·ч (~16 г) либо
> подогрев. Это уточнить при испытаниях.

| Компонент | Рабочий диапазон | Проходит? |

| DC-DC MP1584 | −40…+85 °C | ✅ |

**Вывод:** требование выполняется, но **лидар на −20 °C работает на пределе**.
Для гарантированного запаса по холоду — радар 60 ГГц (A121: −40…+85 °C) или
NRA24 (−40…+85 °C). Рекомендуется **саморазогрев** (подогрев платы) в мороз.

### 3.7. Требование 7: перегрузка 10g осевая / 3g радиальная

**Сила, действующая на элементы** `F = m·a` (a = 10g = 98,1 м/с²):

| Элемент | Масса | Сила при 10g |
|---|---|---|
| Датчик TFmini-S | 11 г | 1,08 Н |
| Корпус | 35 г | 3,43 Н |

**Проверка крепления.** Крепёж M2 (4 винта) на срез: допустимая нагрузка ~50 Н
на винт → запас > 40× ✅.

**Резонанс.** Собственная частота подвеса датчика:
```
f_н = (1/2π)·√(k/m)
```
При жёстком креплении `k ≈ 10⁶ Н/м`, `m = 0,011 кг`:
`f_н = (1/2π)·√(10⁶/0,011) ≈ 1 500 Гц`.

Частота винтов БПЛА 100…200 Гц → коэффициент расстройки `r = 0,07…0,13`,
коэффициент передачи `1/(1−r²) ≈ 1,01` — **резонансного усиления нет** ✅.

**Требования к конструкции:**
- жёсткое крепление датчика (без консольных выступов);
- естественная частота сборки ≥ 2 кГц;
- заливка тяжёлых элементов компаундом;
- фиксация разъёмов (вибростойкие JST-GH с защёлкой).

## 4. Схема работы

### 4.1. Алгоритм (конечный автомат)

См. `hardware/work_algorithm.svg`. Состояния:

| Состояние | Действие | Переход |
|---|---|---|
| **INIT** | инициализация UART, CAN, таймеров | → SELF-TEST |
| **SELF-TEST** | проверка датчика и связи | ок → CONFIG, ошибка → FAIL-SAFE |
| **CONFIG** | приём уставки H_ср по CAN | → MEASURE |
| **MEASURE** | измерение + фильтр (медиана/Калман) | → DECISION |
| **DECISION** | `h ≤ H_ср + v·T`? | да → WARNING, нет → NORMAL |
| **NORMAL** | LED зелёный, флаг = 0, телеметрия | → MEASURE |
| **WARNING** | зуммер + LED красный, флаг = 1, CAN | гистерезис → NORMAL |
| **FAIL-SAFE** | аварийный флаг, LED мигает | при восстановлении → CONFIG |

### 4.2. Временная диаграмма реакции

См. `hardware/timing_diagram.svg`. Моменты времени:

| Метка | Событие |
|---|---|
| t₀ | высота пересекла H_ср |
| t₁ | завершено очередное измерение датчика |
| t₂ | кадр принят MCU (после UART) |
| t₃ | порог сравнён, флаг сформирован |
| t₄ | выход активен (зуммер/LED/CAN) |

### 4.3. Взаимодействие с СУ БПЛА (последовательность)

```
СУ БПЛА ──CAN──▶ [уставка H_ср] ──▶ Датчик
Датчик  ──CAN──▶ [высота, флаг, статус] ──▶ СУ БПЛА
Датчик  ──GPIO─▶ [флаг LOW ALT, открытый сток] ──▶ полётный контроллер
Датчик  ──локально──▶ зуммер + LED (пилот слышит/видит)
```

## 5. Сводка выполнения требований ТЗ

| № | Требование | Решение | Статус |
|---|---|---|---|
| 1 | H_сраб 2…10 м, варьирование | уставка по CAN, шаг 0,1 м, хранение в EEPROM | ✅ |
| 2 | Радар (см/мм) или лазер | радар 60 ГГц A121 (вниз) + 7× VL53L5CX (кольцо) | ✅ |
| 3 | Погрешность ≤ 1 м | ε = 0,08…0,36 м с учётом **всех** источников | ✅ при наклоне ≤ 10° |
| 4 | Реакция ≤ 1 мс (**физическая**) | нужен датчик ≥2 кГц; **A121 (SPI)** проходит, TFmini-S — нет | ✅ при A121 |
| 5 | Масса ≤ 100 г | 88 г с батареей 500 мА·ч (3 ч) | ✅ (запас 12 г) |
| 6 | −20…+40 °C | радар A121 (−40…+85 °C); батарея теряет ёмкость на холоде | ⚠️ запас батареи |
| 7 | 10g осевая / 3g радиальная | F ≤ 3,4 Н, запас крепежа >40×, резонанс не возбуждается | ✅ |
| 8 | **Обзор 360° (земля, стены, потолок)** | кольцо 6× VL53L5CX + 1 вверх + радар вниз | ⚠️ стены до 4 м |

**Открытые пункты:**
1. **№4 — реакция.** Выполнимо только на датчике ≥2 кГц (A121). TFmini-S
   **не проходит**. Нужно паспортное подтверждение и натурное измерение.
2. **№8 — обзор 360°.** Кольцо VL53L5CX видит стены только **до 4 м**.
   Если нужно 10 м во все стороны — только мм-радар, но это +10 000 ₽ и +15 г
   (выход за бюджет/массу). **Уточнить дальность по стенам.**
3. **№6 — холод.** Батарея LiPo на −20 °C теряет 20…30 % ёмкости → 3 ч не
   гарантируются. Нужна батарея больше или подогрев.
